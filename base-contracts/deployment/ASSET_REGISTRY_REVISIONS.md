| Tag | Commit | What it marks |
|---|---|---|
| `registry-revB-2026-10-20` | the commit that adds this section | Current active list: `assetRegistry.revB.json` (Revision B, 487 entries, unchanged since t220u) together with the 2026-10-20 on-chain verification `onchain_verify_20261020.csv` (823 historical EVM token addresses checked; all 475 Revision B tokens pass). |
| `registry-historical-961` | `529d658` | The last commit that changed `assetRegistry.resolved.json` (prior revision, 961 written rows). |

Both are annotated tags pushed to origin. The app offers only assets on the
active list that passed on-chain verification: `src/data/activeAssetAllowlist.json`,
generated by `scripts/buildAppAllowlist.cjs` from `assetRegistry.revB.json` and
`onchain_verify_20261020.csv` (`node scripts/buildAppAllowlist.cjs --check` fails
if it is out of date).

Rows are never relabelled between revisions. Each later file is a strict
subset of the earlier one, with the row fields copied unchanged.

Rebuild the current revision and what depends on it:

```
node scripts/buildRevisionB.cjs            # deployment/assetRegistry.revB.json
node scripts/buildTokenAddressIndex.cjs    # deployment/tokenAddressIndex.json
node scripts/build_ceremony_artifacts.cjs  # scripts/deploy-pages/ceremony-data.json (fetches the ETH price)
node scripts/deploy-pages/buildDeployPages.cjs
```
